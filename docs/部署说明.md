# Linux 部署说明

## 运行布局

使用 Node.js 24 LTS，推荐与本次验证一致的 24.21.0。服务按单实例运行，不启用 PM2 cluster 或多进程共享同一数据库。应用启动会将遗留的“传输中”记录标记为中断。

本说明及 `deploy` 中的示例使用以下路径：

| 项目 | 路径 |
|---|---|
| 程序 | /opt/wangpan |
| Node.js | /opt/node-v24/bin/node |
| SQLite | /var/lib/wangpan/wangpan.sqlite |
| 共享文件 | /srv/wangpan/files |
| 配置 | /opt/wangpan/.env |
| 服务用户 | wangpan |

选择与目标 Linux 架构一致的 Node.js 官方发行包，安装到对应目录。复制程序源码、package.json 和 package-lock.json；不要复制当前 Mac 的 node_modules、.runtime、.cache、.env、data 或测试产物。

## 安装依赖与配置

在目标服务器创建独立用户和目录：

~~~sh
sudo useradd --system --home-dir /opt/wangpan --shell /usr/sbin/nologin wangpan
sudo install -d -o wangpan -g wangpan -m 0750 /opt/wangpan
sudo install -d -o wangpan -g wangpan -m 0700 /var/lib/wangpan
sudo install -d -o wangpan -g wangpan -m 0750 /srv/wangpan/files
~~~

如果用户或目录已存在，检查并复用，避免重复创建。把源码放入 /opt/wangpan 后，在该目录安装与目标平台匹配的依赖：

~~~sh
export PATH="/opt/node-v24/bin:$PATH"
npm ci --omit=dev
npm run setup
~~~

better-sqlite3 是原生模块，必须在目标 Linux 上安装；如果目标平台没有预编译包，安装该发行版的 Python 3、make 和 C/C++ 编译工具后重试。不要沿用 Mac 编译出的二进制文件。

修改 `.env`，保留 setup 生成的独立随机 SESSION_SECRET：

~~~dotenv
FILE_ROOT=/srv/wangpan/files
SQLITE_PATH=/var/lib/wangpan/wangpan.sqlite
HOST=127.0.0.1
PORT=3000
SESSION_SECRET=填写由setup生成的随机密钥
SESSION_HOURS=8
TRUST_PROXY=loopback
COOKIE_SECURE=true
NODE_ENV=production
~~~

`COOKIE_SECURE=true` 对应 HTTPS。仅在明确使用内网 HTTP 时设置为 false。直接访问应用、没有反向代理时，设置 `TRUST_PROXY=false`；如需局域网直连，按网络环境设置 HOST。

程序读取环境变量优先于项目 `.env`。配置路径相对项目目录解析，不依赖执行命令所在目录。更换 SESSION_SECRET 会导致已有浏览器 Cookie 失效。

确保 wangpan 用户能读取程序和配置，并且只有数据库目录可由服务写入。系统管理员负责把文件放入共享目录，服务用户只需读取和遍历权限：

~~~sh
sudo chown root:wangpan /opt/wangpan/.env
sudo chmod 0640 /opt/wangpan/.env
sudo -u wangpan /opt/node-v24/bin/node /opt/wangpan/scripts/init-db.js
~~~

初始化后内置 admin/adminyj@2026、user/yj@2026；后续密码仅由管理员在用户管理页面修改。

## systemd 启动

核对并调整 `deploy/wangpan.service` 中的 WorkingDirectory、ExecStart 和 ReadWritePaths。修改共享目录时，也同步调整 ReadOnlyPaths。

~~~sh
sudo cp deploy/wangpan.service /etc/systemd/system/wangpan.service
sudo systemctl daemon-reload
sudo systemctl enable --now wangpan
sudo systemctl status wangpan
sudo journalctl -u wangpan -n 100 --no-pager
~~~

服务停止时最多等待 20 秒让连接收尾，再关闭剩余连接。SQLite 使用 WAL，文件及同目录的 -wal/-shm 文件均应保留正常读写权限。

## Nginx 与客户端 IP

参考 `deploy/nginx.conf`，替换域名和已准备好的 TLS 证书路径。该示例假定 Nginx 与应用位于同一台服务器，浏览器通过 HTTPS 访问 Nginx。

~~~sh
sudo nginx -t
sudo systemctl reload nginx
~~~

示例覆盖 X-Forwarded-For、X-Forwarded-Host 和 X-Forwarded-Proto，应用仅信任 loopback 代理。若存在多层代理，应将 TRUST_PROXY 改成真实可信代理的明确 IP/CIDR，并检查每层转发头处理。不要配置无条件信任。

所有下载必须经过应用。不要添加绕过应用认证的共享文件 alias、静态目录或 X-Accel-Redirect 规则。本版审计结果以应用流式传输结果为依据，示例关闭 Nginx 响应缓冲。

## 验收

1. 使用两个默认账号登录，确认普通用户看不到用户管理和日志入口，也不能修改密码。
2. 放入一个中文文件和一个子目录，验证逐层浏览、刷新及下载内容一致。
3. 管理员修改普通用户密码，确认旧密码和旧会话失效，重启后保持新密码。
4. 查询同一次登录、下载的 IP 和时间，确认记录的是预期客户端地址而非代理地址。
5. 下载一个较大文件并断开连接，检查下载结果为中断。
6. 检查 systemd 重启、文件权限和 SQLite 目录持久化。正式环境需要在目标服务器完成这些检查。

## 备份与恢复

采用停机复制，完整保留数据库目录，避免只复制处于 WAL 写入过程中的主文件：

~~~sh
sudo systemctl stop wangpan
sudo install -d -m 0700 /var/backups/wangpan
sudo cp -a /var/lib/wangpan /var/backups/wangpan/data-$(date +%Y%m%d-%H%M%S)
sudo systemctl start wangpan
~~~

另外备份 .env 和共享文件目录。恢复时先停止服务，恢复数据库目录和配置，校正 wangpan 用户权限后再启动。保留 SESSION_SECRET 可让尚未到期且未被撤销的会话继续使用。

升级时先备份，替换源码与锁文件，在目标服务器执行 npm ci --omit=dev，再重启服务；不要删除账号或数据库来重新初始化。
